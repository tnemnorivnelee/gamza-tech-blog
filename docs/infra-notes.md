# 인프라 메모

`backend-plan.md`에 없는 인프라 사실을 모아 둔다. 코드에서 알 수 없는 것만 적고, 값이 변하면 날짜와 함께 고친다. 기준일은 2026-11-05이다. 비밀값과 개인키의 경로·내용은 적지 않는다.

## 목표와 예산

- 월 $5 이내(가능하면 무료). 학습과 포트폴리오가 목적이다.
- 옛 백엔드와 인프라는 이전 팀원이 AWS 비용(월 약 7만 원)을 감당하지 못해 내렸다. DB 백업은 그 팀원이 갖고 있다.

## 도메인

- 새 도메인은 `gamza.xyz`(가비아에서 구매, 가비아 기본 네임서버, 2026-11-02).
- 블로그는 `blog.gamza.xyz`. 가비아 DNS에 CNAME `blog`을 Vercel이 알려 준 값으로 추가했고 Vercel `Valid`, HTTPS 200을 확인했다.
- 백엔드 서브도메인은 정하지 않았다(개발하면서 정한다). 쿠키 도메인, CORS 허용 출처, OAuth 콜백은 모두 환경변수로 뺀다.
- 옛 도메인(`gamza.site`, `gamzatech.site`)은 리다이렉트하지 않는다. 홍보 사이트(`www`)는 폐기했다. 프론트에 `gamzatech` 잔재가 남아 있어 정리가 필요하다(별도 이슈, 새 도메인 확정 후 한 번에).

## 프론트 배포

- Vercel에 배포한다. org 레포(`potato-club/GamzaTechBlog-front`)의 `main`에 push하면 `sync-to-fork.yml`이 사용자 개인 포크로 force push하고 Vercel이 빌드한다.
- 프론트는 당분간 Vercel에 두고 백엔드만 컨테이너로 배포한다(잠정). 합치는 것은 백엔드가 안정된 뒤에 다시 논의한다.

## 서버 (OCI)

- 홈 리전은 오사카(`ap-osaka-1`). 한국 리전이 가입 목록에 없었고 변경할 수 없다. 계정은 Free Trial 상태이다.
- 콘솔 마법사로 VCN `gamza-vcn`(공개·사설 서브넷, 인터넷·NAT·서비스 게이트웨이)을 만들었다. NAT·서비스 게이트웨이의 비용 여부는 확인하지 못했다.
- 인스턴스(Ubuntu 24.04, A1.Flex)는 `Out of capacity`로 11회 연속 생성에 실패했다(2026-11-03).
- 무료 A1 한도가 2 OCPU/12GB로 줄었다는 보도가 있으나 시행일이 출처마다 달라 공식 공지를 찾지 못했다.
- 유료 전환(PAYG)은 한도 초과분이 자동 청구될 수 있고 상한을 걸 수 없다는 우려로 보류했다(결정이 아니다).
- **2026-11-05에 판단한다**: OCI를 계속 시도할지, $5 VPS로 갈지. 그때까지는 추가 재시도 없이 로컬 개발만 하기로 했다.
- SSH 개인키는 사용자가 로컬에 보관한다.

## 새 서버 방향 (확정)

- VM 한 대에 Docker Compose: nginx, api, mysql, redis 컨테이너. 리버스 프록시는 Nginx(학습 목적, 인증서 발급 방식은 구현 시 결정).
- Redis는 별도 컨테이너로 두고 데이터 보존 설정(AOF/RDB), 비밀번호, 내부 네트워크 접근만 허용한다. 토큰 저장은 인터페이스 뒤에 둔다.
- DB 백업은 서버 밖에 둔다.
- 미정: CI/CD(GitHub Actions와 Jenkins), 이미지 저장소, 백업 방식.

## 이전 팀원과의 합의

- DB 백업 파일을 암호화해서 전달받는다(2026-11-05경 도착 예정). 개인정보와 평문 GitHub 토큰(`github_tokens`)이 들어 있으므로 복원 규칙은 `AGENTS.md`의 Boundaries를 따른다.
- S3 버킷(`gamzatech-bucket`)을 삭제하지 않도록 요청했다. 옛 이미지 URL이 S3를 가리키며, 복사 전까지 옛 인프라에 기대는 것은 이 이미지뿐이다.
- AWS 비용 내역과 Jasypt 비밀번호는 필수가 아니다.

## 옛 인프라 구조 (README 다이어그램 기준, 실제 운영과 같다는 보장은 없음)

- EC2 한 대에 Docker로 Jenkins, Redis, Nginx, Spring 컨테이너. MySQL은 별도 RDS, 이미지는 Docker Hub.
- 앱은 HTTP만 받고 HTTPS 종단 위치는 알 수 없다(nginx 설정과 인증서가 레포에 없다). 쿠키는 `Secure`로 고정했고 포워딩 헤더 설정은 없다.
- 운영 CORS·쿠키 설정은 옛 레포 `master`와 다를 수 있다.
